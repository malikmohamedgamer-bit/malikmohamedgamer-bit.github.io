# Game Hub

**https://malikmohamedgamer-bit.github.io/** — a server-browser style list of Malik's browser games, with live
player counts, plays, likes, favourites and share links. Installable as an app (Share → Add to Home Screen);
games open inside the app.

Vanilla HTML/CSS/JS with ES modules, no framework, no build step for the page itself. Hosted on GitHub Pages
as the **user site**, so it shares one origin with every game's project site (`/TDS/`, `/Skate-game/` …).

## Layout

```
site/                     what Pages serves (deployed by .github/workflows/discover.yml)
  index.html, css/hub.css, js/app.js     the hub page (list, tabs, sort, search, tags, detail dialog)
  js/stats.js             live stats client (Firebase RTDB + anonymous auth), shared by the hub and the SDK
  hub-sdk.js              loaded by every game: plays, presence, "← Hub" button in the installed app
  firebase-config.js      public Firebase web config (null = stats off, the UI shows "—")
  sw.js                   service worker for hub paths ONLY (see below)
  manifest.webmanifest, icons/, og.png, favicon.ico, 404.html
  play/                   in-app player (/play/?g=<slug>) for games hosted on another origin
  games.json              GENERATED by tools/discover.mjs — never edit by hand
  g/<slug>/               GENERATED share pages with the game's Open Graph tags; they redirect to /?g=<slug>
tools/
  discover.mjs            auto-discovery (no npm deps): topic hub-game → game.json → games.json + g/ pages
  build.mjs               copies site/ to _site/ and stamps the service worker cache version
  icons.mjs               the icon family (hub + every game): SVG masters → favicon/ico/apple/192/512/maskable
  banners.mjs             real 1280×720 gameplay screenshots per game (Playwright + Edge)
  og.mjs                  the hub's share image
  serve.mjs               local server (site/ at /, `--games` mounts the sibling game repos like Pages does)
  test-hub.mjs            Playwright tests (desktop + 390×844, both themes, PWA via CDP, SDK)
  test-rules.mjs          security-rules test with two anonymous users (emulator or --live)
database.rules.json, firebase.json   Realtime Database rules + emulator config
ADD_A_GAME.md             checklist + ready-to-paste prompt for making a new game hub-ready
```

## How discovery works

`.github/workflows/discover.yml` runs on every push to `main`, daily at 05:23 UTC and on manual dispatch:

1. lists the owner's public, non-archived repos with the topic **`hub-game`**;
2. fetches `<homepage or https://malikmohamedgamer-bit.github.io/<repo>/>game.json` and validates it
   (`validateGame` in `tools/discover.mjs`: lengths, slug format, https URLs, repo match …); invalid ones are
   skipped with a warning;
3. writes `site/games.json` (sorted by `addedAt`, plus `updatedAt` = the repo's last push) and
   `site/g/<slug>/index.html`, removes share pages of games that left, and commits only if something changed;
4. builds `_site/` and deploys it to Pages (the daily run deploys only when discovery changed something).

Run it by hand: `gh workflow run discover.yml -R malikmohamedgamer-bit/malikmohamedgamer-bit.github.io`, or
locally `node tools/discover.mjs` (`--check` = dry run, `--validate path/game.json` = check one file).

## Live stats: data model

Firebase Realtime Database + Anonymous Auth on the free Spark plan (project `game-hub-fd83a`, database in
`asia-southeast1`). Every device gets an anonymous uid (shared by the hub and the games, because they are one
origin).

| Path | Value | Who writes |
|---|---|---|
| `/stats/{slug}` | `{plays, likes, dislikes}` | anyone signed in, only ±1 and only with the matching change below |
| `/votes/{slug}/{uid}` | `1` or `-1` | that uid, in the same multi-path update as the matching likes/dislikes change |
| `/presence/{slug}/{uid}` | server timestamp | that uid; removed by `onDisconnect`; refreshed every 60 s |
| `/lastPlay/{slug}/{uid}` | server timestamp | that uid; a play needs the previous one to be > 30 min old |

`database.rules.json` enforces all of it (counter deltas tied to vote transitions, plays tied to a fresh
`lastPlay`, server timestamps only, slug format, no extra fields, no deletes of counters). Reads: `stats` and
`presence` are public; a vote or lastPlay is readable only by its owner. "Online" = presence entries younger than
5 minutes. `tools/test-rules.mjs` proves allowed writes succeed and forbidden ones fail:

```bash
npx firebase-tools emulators:exec --only database,auth --project demo-gamehub "node tools/test-rules.mjs"
node tools/test-rules.mjs --live    # against the real database (uses site/firebase-config.js)
```

The web config in `site/firebase-config.js` is public by design. Never commit service-account keys or tokens.
To deploy rules: `npx firebase-tools deploy --only database --project <project-id>` (needs `firebase login`), or
paste `database.rules.json` into Console → Realtime Database → Rules.

## The service worker trap

`/sw.js` is registered at `/`, so the browser routes fetches for the **whole origin** through it, including
every game. It answers only an explicit allow-list of hub paths (`/`, `/index.html`, hub CSS/JS/icons,
`/games.json` network-first) and returns without `respondWith()` for everything else, so games are never
served stale. `tools/build.mjs` stamps a new cache version on every deploy. Games with their own service
worker (Riftkeep) must ignore URLs outside their own scope, so they never cache the hub's shared files.

## hub-sdk.js

One line in every game: `<script src="/hub-sdk.js" async></script>` (optional `data-hub-corner`,
`data-hub-slug`). After the page's `load` event (+2.5 s) it reads the game's slug from `/<repo>/game.json`,
marks the game in the hub's "Recently played", lazy-loads Firebase, keeps presence, and counts a play at most
once per 30 minutes per device. Automated browsers (`navigator.webdriver`: crawlers, Playwright runs) never
count as plays or presence. It shows a small "← Hub" button only in an installed app (`display-mode`
standalone/fullscreen/minimal-ui or `navigator.standalone`), hides it during pointer lock and fullscreen, and
stops pointer events on it from reaching the game. Every step is wrapped and fails silently.

## Change things

- **Look**: `site/css/hub.css` (tokens at the top: dark `:root`, light `[data-theme="light"]`).
- **List behaviour**: `site/js/app.js` (sorts in `visibleGames`, row markup in `makeParts`).
- **A game's listing**: edit that game's `game.json` in its own repo and push; discovery picks it up.
- **Icons**: `tools/icons.mjs` (one entry per slug), then `node tools/icons.mjs --copy`.
- **Tests**: `npx firebase-tools emulators:exec --only database,auth --project demo-gamehub "node tools/test-hub.mjs"`;
  `node tools/test-hub.mjs --live` checks the deployed hub; `--only desktop,mobile,share,pwa,sdk` picks sections.

Free-plan limits (Spark): 100 simultaneous Realtime Database connections, 1 GB stored, 10 GB/month downloaded.
Each open game tab or hub tab holds one connection.
